## 视角五 · 沉淀判据：什么值得进长期记忆

### 当前 demo 存在的问题（实测证据）

| 问题 | demo 证据 | 影响 |
|---|---|---|
| **无判据全收**：HeuristicExtractor 无条件把"最后一条最终回答"记为 conclusion | 会话2 的元回答「根据【记忆召回】直接汇报：Go 1.27.1，无需重复探索。」也被沉淀，库中多一条无复用价值的记忆 | 长期记忆被噪音污染；Recall 排序只能压分，不能清除 |
| **单源提取**：只盯最终回答，忽略事件信号 | 会话全程只有 read_file（只读）；若含写文件/审批动作，也不会被沉淀为决策记忆 | 高价值"变更/决策"记忆缺失，低价值"回答文本"反而入库 |
| **类别单一**：永远产出 conclusion | 库内条目全部 `[conclusion]` | `categoryWeight`（conclusion=2 > constraint=1.5 > detail=1）的排序优势被浪费 |
| **无反馈验证**：不记录"被召回后是否真的被引用" | 条目无 usage 计数/最近召回时间字段 | 无法区分高价值与噪音；记忆库只增不减 |
| **去重粒度粗糙**：仅 (Content, Category) 完全一致才去重 | 同一结论换措辞会重复沉淀 | 库膨胀，召回信噪比下降 |

根因：沉淀判据放在了"启发式规则"里，而启发式没有判断力——它是**占位实现**，
靠"全收 + 召回排序衰减"兜底，不是"知道该记什么"。

### 判据框架：三问 + 三类信号

**三问**（单条信息是否值得进长期记忆，逐条过闸）：

| 问题 | 值得记 | 不值得记 |
|---|---|---|
| 还会复用吗（价值） | 项目结论、约束、偏好、架构决策 | 一次性执行细节、临时 workaround |
| 会过期吗（稳定性） | 跨会话稳定成立的信息 | 过程性信息（"先试了 A 再试 B"） |
| 能追溯吗（可追溯性） | 来源明确（session:msg / file:line） | 无来源的模糊表述 |

**三类信号**（如何"自动知道"，替代猜）：

1. **显式信号**：模型产出时声明 `memory_worth`（或直接输出记忆条目）——
   把判据交给 LLM，提取器从"全收"变"按标注收"；
2. **事件信号**：不盯最终回答，盯副作用账本——写文件成功、审批通过、
   配置变更这些"改变世界"的事件，天然比回答更值得沉淀（决策/变更类记忆）；
3. **反馈信号（lazy）**：不主动判断，靠使用说话——条目被召回后模型真的
   引用了它 → 权重提升；长期未被召回 → 降权、过期清理。

> 关键：**判据放提取阶段（加信号过滤），验证放召回阶段（使用即强化）**。
> 错收可容忍，误杀才致命——提取时宁可宽，靠召回淘汰。

### 改造方案（落地路径）

1. **提取源升级（事件信号优先）** 🆕
   - 沉淀素材从"最终回答"换成 **Ledger 账本中 SideEffect 为写/审批的动作**
     → decision / constraint 类记忆（"改变了世界"的事件比回答可靠）；
   - 最终回答仅当含显式标注（`memory_worth` / 结论信号词）才沉淀为 conclusion。
2. **显式标注通道** 📋：LLM 版提取器产出结构化记忆条目
   （Content / Category / memory_worth），启发式保留为默认兜底。
3. **反馈闭环（lazy 强化）** 🆕：`MemoryEntry` 增 `usage_count` /
   `last_recalled_at`；Recall 命中后调用方回写引用 → 权重乘数（被用过=有价值）；
   长期未召回 → 降权、过期清理（新接口 `Forget` / `Prune`）。
4. **类别覆盖** 📋：提取器按内容特征分类——含"结论/因此/综上"→conclusion；
   "决定/采用/放弃"→decision；"禁止/必须/不能用"→constraint；
   "偏好/倾向/喜欢"→preference，让类别权重真正生效。
5. **去重增强** 📋：至少按（会话, 主题）维度去重；可选 LLM 语义去重。

### 与既有机制的映射（复用不新造）

- **Ledger（步骤账本）** ✅ → 事件信号源（已记录"执行了什么动作"）；
- **审批点** ✅ → decision 类记忆的触发（审批通过 = 明确决策事件）；
- **SideEffect 风险分级** ✅ → 变更类记忆的触发条件（写/审批才沉淀）；
- **Recall 关键信息优先排序** ✅ → 反馈强化的载体（加 usage 权重维度）。

## 优先级结论

1. **立即（下轮实现）**：提取源加"事件信号"（Ledger 写/审批动作 →
   decision/constraint 记忆），补 `usage_count` / `last_recalled_at` 字段与
   Recall 引用回写——改动集中在 memory 包，不破坏现有 demo 与测试。
2. **中期（第 5 步收尾时）**：LLM 版提取器（显式标注通道），启发式降为兜底。
3. **长期（第 8 步评测深化）**：记忆库健康度指标——"召回命中率 / 引用率"，
   把"沉淀质量"从定性讨论变成可评测的回归基线。
