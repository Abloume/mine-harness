## 视角一 · 分层架构与契约设计

> 核心原则：谁决策、谁执行、谁供能——每层只做一件事，层与层之间只走结构化信封，不走共享内存。

| 原则 | 与 mine-harness 现状的对照 | 状态 |
|---|---|---|
| **分层拓扑**：L1 编排决策 / L2 执行单一职责 / L3 能力供能 | 已按「机制归内核、工具归应用层」分层；第 7 步多 Agent 编排 = 补 L1 Planner + L2 Worker | 📋 |
| **跨层契约**：任务信封（目标/输入/约束/验收标准）、结果信封（产物/证据/状态/错误） | 已有同构雏形：评测结构化 JSON、RunResult 带原因；第 7 步落成 TaskEnvelope / ResultEnvelope 结构体 | 🆕 |
| **职责分界**：决定权留在上一层——编排者持计划与全局上下文，负责重试/重派/降级；Worker 无状态、只拿任务切片 | 软停止「交还用户」语义已对齐；重试/降级决策应归 Planner 而非 Worker | 📋 |
| **规划层四子模块**：意图拆解 / Skill 分析 / Skill 动作 / 运行时参数注入 | Skill B 方案已分离「发现（常驻清单）+ 动作（load_skill）」；缺 Skill Params 动态注入运行时配置 | 🆕 |
| **反馈与记忆层**：Observation / Skill History / Prompt Update | 短期记忆 = 压缩 + LLM 摘要（6 段式）已有；缺 Skill History（记录调用成败、防重复无效调用） | 🆕 |
| **工具执行层**：注册中心 + 幂等性 + 沙箱隔离 | Registry、超时 + 进程组杀灭已有；通用幂等性声明缺失 | 🆕 |

## 视角二 · 生产化验收标准

> 核心原则：能跑通正常路径不算数，处理过真实失败场景才算落地。

| 验收项 | 与 mine-harness 现状的对照 | 状态 |
|---|---|---|
| **工具调用稳定性**：指数退避重试 / 结果 schema 校验 / 异常降级兜底 | 指数退避已有；工具返回结果未做 schema 校验，模型可能「以为成功了」 | 🆕 |
| **记忆分层**：多轮上下文管理 + 关键信息优先召回 | 压缩 + LLM 摘要（6 段式已保关键信息）已有；长期记忆分层 = 第 5 步 RAG | 📋 |
| **跑偏兜底**：最大步数 / 死循环终止 / 内容审核 / Token 成本控制 | 循环检测 N=2 + 滑动窗口 8 + 重试预算 3；usage 触发压缩、关 thinking、隐式缓存全部落地 | ✅ |
| **状态机 vs 线性链**：节点级可重试 / 分支失败回滚 / 防单点拖垮全链 | 当前为线性循环 + 软停止；第 6/7 步按状态机思路设计节点级重试与回滚 | 🆕 |
| **工程三件套**：日志重放 / 关键节点断言 / Bad Case 闭环复盘 | = 第 8 步可观测性：结构化轨迹导出 + 回放 + 对抗用例评测门 | 📋 |

## 优先级结论

1. **先补（改动小、直击验收追问点）**
   - 工具返回结果 schema 校验：给工具声明返回 schema，回填前校验，失败走明确错误。
   - Skill History 短期工作记忆：环形 buffer 存最近 N 步调用摘要，压缩时并入摘要。
2. **第 7 步开工前定契约**：TaskEnvelope / ResultEnvelope 结构体 + 决定权留 Planner + 状态机化节点重试。
3. **印证方向已对**：README 踩坑记录（thinking max_tokens、进程组杀灭、摘要收敛护栏）正是「故障倒逼」的产物——继续保持记录新坑的习惯。

## 对后续步骤的映射

- **第 5 步 RAG**：兑现「记忆分层 + 关键信息优先召回」（视角二）+ 长期记忆（视角一反馈层）
- **第 6 步工作流 Skill**：按状态机思路做节点级可重试、分支回滚（视角二）
- **第 7 步多 Agent 编排**：信封契约 + 决定权留上层（视角一全文落点）
- **第 8 步可观测性**：日志重放 + 关键节点断言 + Bad Case 闭环（视角二工程三件套）
