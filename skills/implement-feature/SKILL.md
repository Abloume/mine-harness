# 实现功能（加载上下文 → 规划 → 写码 → 验证 → 复核）

## 何时加载

任务描述要求新增能力/行为（不是修既有错误）时加载。修复回归用 fix-bug，
测试红了先修用 run-tests-fix。

## 流程（一次一个 ticket 小闭环，产物即任务切片，不做长 Chain）

1. **加载上下文**：读相关模块源码 + 既有测试，了解约定（命名/错误处理/边界）与
   可复用机制；不重复造轮子（机制归内核、工具归应用层的边界先查 AGENTS.md）；
2. **规划实现**：明确「改哪些文件、新增什么、验证方式、验收标准」——
   对终点具体、对手段放权；一次只做一个 ticket；
3. **写码**：按仓库约定（Go 标准库优先）；新能力必须配套 `-demo` 场景 +
   单元测试（新增机制放 internal/xxx 包 `*_test.go`）；
4. **验证**：目标包测试 → 全量 `go build ./... && go test ./...` →
   边界自查（空/超范围/并发/取消）；
5. **复核**：diff 复核只含本 ticket 改动；对照规划阶段的验收标准逐项勾。

## 验证清单（逐项勾完才算完成）

- [ ] 目标包 + 全量测试全绿
- [ ] 新能力有 demo 与单测（按 dev-add-demo Skill 流程注册）
- [ ] diff 只含本 ticket 改动
- [ ] 验收标准逐项勾完（含边界）

## 失败时怎么停

- 写到一半发现方向不对：先停，不把半成品堆进仓库（git 未提交前可还原）
- 验证不过：修到绿再继续；同一问题 3 次不收敛：停下汇报
