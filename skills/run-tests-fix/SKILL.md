# 跑测试修失败（全量跑 → 逐条修 → 重跑到绿）

## 何时加载

任务要求跑测试、修失败用例、补测试覆盖时加载。既有功能行为错误用 fix-bug。

## 流程（失败清单是锚点，逐条收敛，不做长 Chain）

1. **跑全量拿失败清单**：`run_cmd` 的 `go test ./... -v`（或目标包），把失败用例
   逐条记下（用例名 + 断言失败输出）；
2. **按根因归类**：多个失败常是同一根因（共享初始化/公共函数），先修根因再批量；
3. **逐条修复**：修实现或修测试本身（测试断言与实现约定不一致时，先确认哪个是
   真预期，再改）；**让测试变绿但绕过断言（删断言/注释用例/放宽阈值）不算修复**；
4. **重跑该包**直到绿，再跑全量确认无新红；
5. **复核**：失败清单每条都有对应修复点（diff 可指认），不是删测试。

## 验证清单（逐项勾完才算完成）

- [ ] 全量 `go test ./...` 绿（含被修包）
- [ ] `go test -race ./...` 相关包绿
- [ ] 失败清单每条都有修复点，未删/未绕过断言
- [ ] 修复后无新引入的失败

## 失败时怎么停

- 单条用例 3 次不收敛：停下汇报（可能是约定分歧，需与用户确认预期）
- 全量跑出与本次无关的存量红：先修本次目标，存量红单独汇报不混改
