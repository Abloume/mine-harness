# 前端视觉验证（起服务 → 截屏 → 核对 → 修复 → 再验证）

## 何时加载

任务涉及前端页面改动需要确认渲染效果（布局/溢出/间距/文案/响应式），或用户
明确要求"看一眼页面长啥样"时加载。纯逻辑改动不适用。

## 流程（截图证据驱动，闭环到问题清单清空，不做长 Chain）

1. **起服务**：`serve_dir` 起本地预览（参数 `{"dir":"webdemo","port":0}` 自动选
   空闲端口），拿到访问 URL；
2. **截屏**：`screenshot` 截关键视口（桌面 1280 宽 / 移动 375 宽分别验证），
   保存 PNG；截图是视觉核对的事实证据；
3. **视觉核对**：把截图交给视觉模型核对验收清单——布局（无溢出/错位）、
   文案（无截断/缺字）、间距（符合设计意图）、响应式（窄屏可用）——
   产出问题清单（每项带位置与严重度）；
4. **修复**：`edit_file` 改 html/css（写类正常走审批）→ 再截屏 →
   与前一张对比核对；
5. **循环**到问题清单清空，或剩余项经评审明确"接受不修"。

## 验证清单（逐项勾完才算完成）

- [ ] 每个验收项（布局/文案/间距/响应式）都有对应截图证据
- [ ] 修复后新旧截图已对比（同视口）
- [ ] 问题清单明确：已修复 or 经评审接受
- [ ] 服务已停止（serve_dir stop），不留常驻进程

## 失败时怎么停

- 截图失败（Chrome 不可用/超时）：如实说明，降级为 DOM 文本核对，不假装已视觉验证
- 修复不收敛（同一问题 3 轮未清）：停下汇报，列出剩余问题清单
