# 经验入库（外部对话 → fe-practices）

## 何时加载

任务是把一段外部经验（豆包对话原文、笔记、踩坑记录）整理进 fe-practices 时加载。
纯讨论、不涉及知识库写入时无需本 Skill。

## 流程（每步独立小闭环，产物逐段可核）

1. **输入采集**：拿到原文（对话 / 笔记 / 报错+修复），尽量保留上下文（场景、代码、报错原文）——
   理由通常藏在上下文里，只贴结论会让「理由」段缺料；
2. **四段式抽取**：每条经验整理为「场景（触发条件）/ 规则（应该怎么做）/ 理由（为什么）/ 反例（错误做法）」，
   格式与 fe-practices 现有条目完全一致；
3. **去重与冲突**：与现有条目比对——
   - 重复 → 跳过或补理由（不新增重复条目）；
   - 冲突（旧条目过时 / 被新经验推翻）→ 修订旧条目并注明；
   - 相似但不同场景 → 新增独立条目；
4. **产出 diff**：明确「新增 N 条 / 修订 M 条」+ 建议插入分组，交宿主确认后再写入；
5. **合并写入**：edit_file 写入 `skills/fe-practices/SKILL.md`（写类动作正常走审批闸门）；
   条目扩充导致 frontmatter 的 description 不再覆盖时同步更新；
6. **验证闭环**：跑 `go test . -run TestRepoSkillsDiscoverable`（发现 + 格式校验必须绿）→
   自查条目数、分组与编号连续性。

## 验证清单（逐项勾完才算完成）

- [ ] 每条含「场景 / 规则 / 理由 / 反例」四段
- [ ] 与既有条目比对过，无重复
- [ ] 冲突条目已修订并注明原因
- [ ] 分组与编号连续，description 覆盖同步
- [ ] `go test . -run TestRepoSkillsDiscoverable` 绿

## 失败时怎么停

- 原文信息不足（缺场景或缺理由）→ 停下问来源 / 上下文，不猜；
- 抽取结果与既有知识库大面积冲突且无法判断谁对 → 停下列出冲突点，交宿主决策；
- 写入前校验失败 → 不强行提交，先修条目格式再重跑验证。
