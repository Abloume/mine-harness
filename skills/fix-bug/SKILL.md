# 修复 bug（复现 → 定位 → 修改 → 验证）

## 何时加载

任务描述指向既有代码行为错误（报错 / 结果不对 / 测试红 / 回归）时加载。
新功能/新行为不在此列（用 implement-feature）。

## 流程（每步独立小闭环，任一步失败都有回滚路径，不做线性 Chain）

1. **复现（先有失败证据）**：读相关测试与源码；跑复现命令（`run_cmd` 的 `go test ./...` 或运行脚本），
   把失败输出原文记下来——它是后续所有判断的锚点。复现不了就如实说"无法复现"，不猜测根因；
2. **定位根因**：用 grep / read_file 顺失败栈找源头；区分「症状」与「根因」——
   只修根因，修症状不收敛；定位靠证据（栈/测试断言/输入输出对比），不靠读代码猜；
3. **最小修改**：`edit_file` 精确替换，一次只改根因处，不顺手重构无关代码；
   写类动作正常走审批闸门；
4. **验证闭环**：重跑复现命令（必须从红到绿，并对比前后输出）→ 跑全量
   `go build ./... && go test ./...`（或目标包）→ 边界自查（空输入/超范围/并发/取消
   是否被本次改动影响）；
5. **复核**：diff 只含根因改动；对照第 1 步的失败输出逐条确认都已转绿。

## 验证清单（逐项勾完才算完成）

- [ ] 复现命令输出从红到绿，前后输出已对比
- [ ] `go build ./... && go test ./...` 全绿（或目标包全绿）
- [ ] diff 只含根因改动，无顺手重构
- [ ] 边界自查完成（空/超范围/并发/取消）

## 失败时怎么停

- 复现命令 3 次不收敛：停下汇报，不换等效方式硬绕
- 定位不到根因：缩小范围（git 二分 / 注释排除法），不盲改
- 修改引入新红：先还原该文件（git 未提交前可还原；已备份走 backup/），换思路
