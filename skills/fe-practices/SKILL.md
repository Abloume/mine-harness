# 前端实践规范

适用：任何编写或修改前端页面 / 组件 / Electron 渲染层的任务。
加载后逐条对照，命中适用场景的条目必须遵守；每条按「场景 / 规则 / 理由 / 反例」组织。

## 一、交互与反馈

### 1. 高频触发保护
- 场景：任何带点击 / 提交的按钮，输入搜索等高频触发
- 规则：必须加防抖（debounce）或节流（throttle），防止用户频繁触发
- 理由：防抖合并连续触发（搜索 / 提交），节流限频（滚动 / 拖拽）；否则重复请求、重复提交
- 反例：无保护的 onClick 直接发起请求

### 2. 跳转反馈
- 场景：目录 / 列表页跳转产品详情页等耗时导航
- 规则：跳转中 toast 提示「正在跳转，请稍等」，完成 / 失败后给结果反馈
- 理由：消除等待焦虑；失败时可定位是网络还是路由问题
- 反例：点击后页面长时间无响应，用户以为没点中又点了一次

### 3. 提交防重
- 场景：提交 / 保存 / 支付类按钮
- 规则：提交中按钮置 loading + disabled，与防抖配合使用
- 理由：防抖挡高频误触，disabled 挡逻辑上的重复提交（双击 / 回车连发）
- 反例：提交中按钮仍可点击，后端收到两条相同请求

## 二、布局与样式

### 4. 自适应宽度
- 场景：宽度自适应的卡片 / 容器
- 规则：不写死 width，仅设置 margin / padding，靠内容撑开或 flex / grid 分配
- 理由：写死宽度在不同断点会溢出；margin / padding + 弹性布局天然自适应
- 反例：`width: 360px` 的卡片在窄屏溢出

### 5. 媒体尺寸占位
- 场景：图片 / 视频 / 异步加载内容
- 规则：预设宽高或 aspect-ratio 占位，再加载内容
- 理由：防 CLS（布局抖动）——内容加载后页面跳动，影响阅读与交互
- 反例：图片加载完成前容器高度为 0，加载后整页下移

## 三、请求与异步

### 6. 请求竞态防护
- 场景：搜索联想、切换 tab / 分页、快速连续操作
- 规则：丢弃过期响应——请求序号比对，或用 AbortController 取消旧请求
- 理由：旧请求晚返回会覆盖新结果，展示与用户意图不一致
- 反例：快速输入两轮搜索，第一轮结果后到覆盖了第二轮结果

### 7. 请求三态覆盖
- 场景：任何异步请求
- 规则：loading / error / empty 三态都要有界面，成功只是其中一态
- 理由：只处理成功路径时，失败与空数据表现为白屏且无提示
- 反例：catch 里只 console.log，用户看到永远转圈

## 四、React 渲染

### 8. 卸载后不 setState
- 场景：组件卸载后仍有异步回调（定时器 / 请求 / 订阅）
- 规则：cleanup 里清理定时器与订阅；回调执行前判断是否已卸载
- 理由：防止内存泄漏与 "setState on unmounted component" 警告
- 反例：setInterval 不清理，组件销毁后仍周期性 setState

### 9. 列表 key
- 场景：列表渲染
- 规则：用稳定且唯一的 key，列表有增删改时不用 index
- 理由：index 作为 key 在元素重排时复用错乱（输入框内容串行、状态错配）
- 反例：`key={index}` 且列表支持删除中间项

### 10. 派生计算缓存
- 场景：渲染函数里的重计算 / 每次新建的对象 / 大数组 filter/map
- 规则：useMemo / useCallback 缓存，依赖数组写全
- 理由：每次渲染重复计算浪费性能；依赖漏写会导致闭包捕获旧值
- 反例：render 里对万级数组裸跑 filter 再 map

## 五、Electron / 桌面

### 11. 渲染进程不直接碰 Node
- 场景：Electron 应用
- 规则：preload + contextBridge 白名单暴露 IPC，渲染进程不开 nodeIntegration
- 理由：渲染进程可能加载远程内容，直接开 Node 权限有 RCE 风险
- 反例：`nodeIntegration: true` 且未禁 remote

## 六、性能

### 12. 长列表虚拟滚动
- 场景：千条级列表 / 表格 / 日志流
- 规则：虚拟滚动（react-window / react-virtualized）或分页，不一次性渲染全部 DOM
- 理由：万级 DOM 节点导致渲染与滚动卡顿
- 反例：直接 map 渲染 5000 行数据

## 七、一致性

### 13. 文案与格式化集中
- 场景：用户可见文案、时间 / 金额格式化
- 规则：文案走常量 / i18n，格式化用统一工具函数，不散落硬编码
- 理由：散落硬编码改动要全局搜索且易漏，口径不统一
- 反例：五个页面各自写 "2026/10/14" 与 "2026-10-14" 两种格式
